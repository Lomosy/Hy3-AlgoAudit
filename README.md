# Hy3-AlgoAudit

> 面向算法竞赛的解题过程评估与错误定位系统

本项目为**个人/活动作品**，非腾讯官方发布。基于腾讯混元大语言模型 [Hy3](https://github.com/Tencent-Hunyuan/Hy3) 构建，用于「犀牛鸟开源·实战任务」之任务二——**可验证场景：过程评估与错误定位**。

---

## 一、项目背景

大语言模型在代码生成与算法推理上的能力持续提升，已能对相当一部分算法竞赛题生成可执行的正确代码。然而，传统在线判题（OJ）只能通过测试用例给出 AC / WA / TLE / RE 等**结果状态**，无法回答更深层的问题：

- 模型是否正确理解了题意与约束？
- 所选算法是否在理论上成立？
- 推导过程是否存在跳步、错误假设或逻辑漏洞？
- 复杂度分析与边界处理是否准确？
- 即使代码通过了测试，推理过程是否真的能支撑这个结果？

因此，算法代码的评测需要从「**结果评价**」扩展到「**结果评价 + 过程评价**」。

本项目依据任务二的要求，选择**算法竞赛**作为目标场景，构建一个同时具备**算法题自动求解**与**解题过程评估**能力的应用，重点解决：

> 程序结果能验证「做对没有」，过程评估器进一步判断「为什么对、为什么错、从哪里开始错」。

---

## 二、技术方案

### 2.1 总体思路

项目采用「**结构化解题 + 沙箱结果验证 + 过程评估 + 首错定位 + 定向修复**」的整体路线，围绕算法竞赛题目的**解法思路、复杂度分析与边界处理**展开过程层面的评估。

### 2.2 双轨评估

系统将一道题目的解答正确性拆分为两个相互关联、但不能相互替代的维度：

| 维度 | 验证方式 | 回答的问题 |
|---|---|---|
| **结果正确性** | 沙箱编译运行 + 测试用例 | 程序是否满足输入输出要求 |
| **过程正确性** | 结构化推理审查 | 推理链条是否成立、错误从哪一步开始 |

其中，「**结果正确但过程不成立**」（例如恰好通过测试用例、但实现逻辑或论证存在缺陷）是本项目重点识别的一类样本。

### 2.3 结构化解题

为保证过程错误可被明确定位，系统将解答统一组织为标准化步骤（题意理解 → 关键观察 → 算法设计 → 正确性推导 → 复杂度分析 → 边界条件 → 最终实现），从而把「这篇题解有问题」转化为「首个错误发生在哪一步」。

### 2.4 过程评估与错误定位

过程评估器采用**多层次评估**方式：对可确定的问题先用规则与结构检查、执行结果用沙箱验证、语义层面再交由模型分步骤审查，最终定位**最早出现的因果错误**并归纳错误类型。

### 2.5 定向修复闭环

区别于「错了就整体重新生成」，系统根据错误发生的步骤与类型，仅对受影响的范围进行定向修改，形成「生成 → 评价 → 定位 → 修复 → 再评价」的闭环。

> 说明：以上仅描述宏观技术路线，核心算法、评估器内部机制与实验设计等细节不在本公开文档中展开。

## 三、系统架构

```
┌────────────────── 用户交互层 ──────────────────┐
│           AI 自动解题        用户解答评估        │
└───────────────────────┬───────────────────────┘
                        ▼
            ┌── 输入与标准化处理 ──┐
            └──────────┬──────────┘
                       ▼
            ┌── 结构化题解生成 ──┐
            └──────────┬──────────┘
           ┌───────────┴───────────┐
           ▼                       ▼
   ┌── 结果验证（沙箱） ──┐   ┌── 过程评估 ──┐
   │  编译 / 运行 / 判定   │   │  分步审查 /    │
   │  AC / WA / TLE / ... │   │  首错定位 /    │
   └──────────┬───────────┘   │  错误归类      │
              │               └──────┬────────┘
              └──────────┬───────────┘
                         ▼
              ┌── 证据融合与诊断 ──┐
              │ 过程判定 / 首错 / 归类│
              └──────────┬──────────┘
                         ▼
              ┌── 定向修复（可选） ──┐
              └──────────┬──────────┘
                         ▼
              ┌── 结构化评估报告 ──┐
```

各模块通过统一的数据流串联，模型能力调用完全基于 Hy3 完成，不涉及训练或微调。

## 四、预期效果与交付物

### 4.1 预期效果

- 形成一套可运行的算法竞赛智能解题与过程评估应用；
- 在输出最终答案的同时，给出完整解答过程，并判断过程是否成立；
- 对错误解答定位首个错误步骤并归纳错误类型；
- 识别「结果正确但过程不成立」的样本；
- 按难度分层分析模型能力边界与主要失败模式。

### 4.2 交付物

- **开源项目仓库**：应用源码、过程评估模块、README、环境配置样例与运行说明；
- **评测材料**：分层题集及标准答案、答案校验脚本、过程评估脚本；
- **完整评测结果**：最终答案准确率、过程正确率、错误类型分布、难度分层结果；
- **有效性验证**：定位准确率与误报率的验证数据及人工抽检记录；
- **分析报告**：过程评估方法设计依据、错误分类体系说明、典型案例分析、能力边界与临界点分析；
- **演示材料**：时长 2 分钟以内的 demo 视频或 GIF，展示一次完整的解题与过程评估流程。
